# Локальный выпуск Sadness VPN 3.4.8

Проверка: 7 ноября 2026 года. Подготовлен локальный комплект Windows x64;
публикация и изменение установленного клиента не выполнялись.

## Состояние исходников

`sadnessvpn-3.4.8.bundle` — инкрементальный Git bundle от `cc17d58` до
`f19771070d34e8a3608cf3fb7193730f70392c4d`. Проверка `git bundle verify`
успешна. Все три коммита уже присутствуют в текущей ветке
`security/api-hardening`; повторное применение не требуется.

Изменения бандла: секрет Clash API на каждый запуск Python, заголовки
авторизации запросов к ядру, токен локального Flask API, передача токена
Electron через заголовок и httpOnly cookie, версия и заметки 3.4.8.
Токен в пользовательском каталоге не изолирует приложение от вредоносного
кода, уже имеющего доступ к файлам этого же пользователя.

Незакоммиченные изменения установщика, тестов отката и release.ps1 существовали
до этой работы и сохранены. Файл `BOOST.md`, указанный в переданных инструкциях,
не найден в проекте и проверенных родительских каталогах.

## Карта проекта

| Слой | Основные файлы и ответственность |
| --- | --- |
| Оболочка | `electron/main.js`, `electron/lib/backend.js`: окно, трей, запуск и корректная остановка Python, токен API |
| Интерфейс | `ui/templates`, `ui/static`: Flask отдаёт страницу, Electron её отображает |
| API | `backend_main.py`, `ui/server.py`, `ui/routes`: HTTP и WebSocket, жизненный цикл подключения и команды оболочки |
| Профиль | `ui/profile_state.py`, `ui/app_state.py`, `engine/paths.py`: подписки, серверы, настройки и расположение данных |
| VPN | `engine/core_config.py`, `engine/mihomo.py`, `engine/ping.py`: конфигурация Mihomo, процесс ядра, проверки связи |
| Маршруты | `engine/routing_rules.py`, `engine/app_routes.py`: правила и назначения приложений |
| Дополнительные движки | `engine/amneziawg.py`, `engine/zapret.py`: WireGuard/AmneziaWG и Zapret |
| Обновление | `ui/update_api.py`, `engine/updates.py`, `engine/update_manifest.py`: выбор пакета, подпись, хеши и загрузка |
| Установка | `installer/updater_main.py`, `installer/recovery_cache.py`, `installer/build_msi.py`, `installer/build_patch.py`: MSI/MSP, резерв и откат |
| Выпуск | `tools/build_candidate.py`, `tools/micro_test.py`, `tools/release.ps1`: сборка кандидата и проверки |

Установленный профиль находится вне каталога программы:
`%LOCALAPPDATA%/SadnessVPN/data`. Исходники по умолчанию используют `./data`.
Для unittest нужно `discover -s tests -t .`: пакет `tests` заранее включает
временный каталог. Живые тесты протоколов используют loopback без TUN.
При остановке оболочка сначала просит Python выключить движки, чтобы не
оставить работающий туннель. Учёт принадлежащих приложению процессов находится
в `engine/owned_process.py`.

## Исправления процесса проверки

- `tools/micro_test.py`: изоляция профиля через `-t .`; запуск проверки
  маршрутизации интерфейса, которую требует барьер публикации.
- `tools/regression_212.py`: полноценный тестовый сервер; подмена потоков
  ограничена модулем сервера и не ломает subprocess в Windows.
- `tools/regression_220_ui.cjs`, `tools/regression_3011_ui.cjs`: стандартный
  браузер Playwright вместо пути к отсутствующей конкретной сборке Chromium.
  При необходимости путь задаётся через `SADNESS_TEST_CHROMIUM`.

Эти изменения относятся к проверкам, поэтому готовые MSI/MSP из кандидата
не пересобирались и их хеши сохранены. EXE собран штатным
`tools/build_setup_exe.py` из проверенного MSI.

## Проверки

- 580 модульных тестов, включая авторизацию API и сценарии обновлятора.
- 17 интеграционных проверок подписок и маршрутизации через Flask API.
- Валидация 15 конфигураций протоколов самим Mihomo и шести типов правил.
- DNS, XHTTP, остальные протоколы, Hysteria 2 и параллельные маршруты на loopback.
- Две проверки интерфейса в headless Chromium.
- Хеши всех файлов кандидата и соответствие MSI в EXE исходному MSI.
- ProductVersion/ProductCode и реальные таблицы MSI: `CacheRecoveryMsi`
  имеет тип 3666 и условие `NOT REMOVE AND NOT PATCH AND NOT MSIPATCHREMOVE`.
- Для каждой базы 3.4.3, 3.4.4, 3.4.6, 3.4.7 повторно сверены хеш патча,
  существующий отчёт административной установки и все 545 файлов уже
  пропатченного образа с полной сборкой. Новая установка патчей не выполнялась.

Результаты: `dist/candidate/3.4.8/test-report.json` и отдельные логи в том же
каталоге; дополнительная сверка пакетов:
`build/codex-3.4.8-package-verification.json`.

## Ограничения и установка

Полный цикл установки и отката на установленном клиенте не проверен для этих
хешей. Во время работы установлена и запущена 3.4.7. Предыдущий неуспешный
откат 1603 относится к старым пакетам с другими хешами; текущий MSI содержит
исправление, но это не заменяет живой тест отката. Проверки реального VPN,
трея и сохранности профиля после установки владельцем также остаются открытыми.
В отчёте кандидата `ready` остаётся `false`.

Для ручной установки завершите Sadness VPN, включая значок в трее, и запустите
`SadnessVPN-3.4.8-Setup-x64.exe`. Он содержит полный MSI. Отдельный MSI —
альтернатива тому же установщику. MSP предназначены только для соответствующих
базовых версий, указанных в именах файлов.

Локальные MSP не включают опубликованный подписанный манифест. Автоматическая
раздача через приложение требует отдельной подготовки и публикации релиза;
по запросу пользователя она не выполнялась.
