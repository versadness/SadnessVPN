# Mihomo TUN и Zapret/winws: путь пакета и честные границы

Два компонента решают разные задачи и работают на разных уровнях. Считать, что
они «просто совместимы», нельзя: WinDivert видит и внешнее соединение самого
туннеля, а стратегия Zapret понимает далеко не любой протокол.

## Кто что перехватывает

| Компонент | Где работает | Что видит |
| --- | --- | --- |
| Mihomo | TUN-адаптер `SadnessMihomo` (Wintun) + правила маршрутизации | исходный трафик приложений до шифрования |
| winws + WinDivert | сетевой уровень Windows, фильтр по портам и протоколам | пакеты на проводе, уже после Mihomo |

Ключевой факт: **трафик внутри туннеля Zapret не видит**. Он зашифрован и
снаружи выглядит как одно соединение с VPN-сервером. Обход DPI внутри туннеля
не нужен и невозможен.

## Путь пакета по режимам

| Режим | Mihomo | Zapret |
| --- | --- | --- |
| Только Mihomo | весь трафик по правилам, TUN поднят | не запущен |
| Только Zapret | не запущен | обрабатывает трафик по портам своей стратегии |
| Mihomo + Zapret, режим «весь компьютер» | почти всё уходит в туннель | обрабатывает только то, что осталось снаружи: DIRECT-правила, исключения локальной сети и служебный трафик |
| Mihomo + Zapret, «только выбранные приложения» | в туннель идут выбранные | всё остальное идёт напрямую и **попадает** под фильтры Zapret |
| DIRECT-правило внутри TUN | пакет выходит мимо туннеля | попадает под фильтры Zapret |
| Разные серверы для разных приложений | каждое приложение в свой outbound | внешние соединения всех этих серверов исключены из перехвата |

Отсюда практический вывод, который показывается и в интерфейсе: связка «VPN на
весь компьютер + Zapret» **не** означает «обход работает для всего ПК». В этом
режиме обход применяется к остатку трафика вне туннеля. Наибольший смысл связка
имеет в режиме «только выбранные приложения через VPN».

## Защита внешнего соединения туннеля

Самая опасная ошибка связки — десинхронизация самого VPN-соединения: оно идёт
на те же 443/80, что и обычный трафик, и попадает под `--wf-tcp`/`--wf-udp`.

Перед каждым запуском обхода приложение записывает адреса используемых
VPN-серверов в `lists/ipset-exclude-user.txt` — этот файл все профили Flowseal
уже передают ядру через `--ipset-exclude`. См. `engine/zapret_exclusions.py`.

* Собираются только адреса **используемых** серверов: выбранного на главном
  экране и тех, что назначены явным маршрутам. Резолвить всю подписку незачем.
* Управляемый блок ограничен маркерами: собственные строки пользователя в этом
  файле сохраняются.
* В файл попадают только IP-адреса. Пароли, UUID, ключи и ссылки подписки — нет.

## Что исключено по конструкции

| Риск | Что сделано |
| --- | --- |
| Повреждение внешнего соединения с VPN-сервером | адреса серверов в `ipset-exclude-user.txt` |
| Повторный захват уже обработанного трафика | winws работает только на портах своей стратегии; трафик туннеля исключён |
| Конфликт экземпляров WinDivert/winws | чужой `winws.exe` обнаруживается и **не** завершается: запуск отменяется с объяснением |
| Конфликт портов ядра | занятый порт — отказ запуска до создания TUN, чужие процессы не трогаются |
| Зависшие собственные процессы | останавливается только собственный процесс; `stop()` ждёт освобождения порта |
| Петли DNS | адреса VPN-серверов резолвятся **до** поднятия TUN и фиксируются в `hosts`; `dns-hijack` перехватывает 53 внутри TUN |
| Молчаливый уход маршрута в DIRECT при сбое GeoSite/GeoIP | конфигурация проверяется ядром до применения: отсутствующая категория — явный отказ |

## Границы, которые нельзя обещать

* Zapret не чинит блокировку, не связанную с DPI (блокировка по IP, отказ
  сервиса, региональные ограничения на стороне сервиса).
* Стратегия HTTP/TLS/QUIC не применяется вслепую к произвольным игровым
  пакетам: расширение диапазонов включает игровые секции профиля, а не
  переписывает браузерные.
* Домен виден Zapret только там, где он есть в открытом виде (SNI, Host). При
  браузерном DoH/ECH и в трафике без доменного имени фильтр по спискам сайтов
  не срабатывает — остаётся фильтр по портам и адресам.
* Sniffer в конфигурации выключен: правила по домену работают за счёт DNS,
  перехваченного TUN (`dns-hijack`, режим `redir-host`). Если приложение не
  спрашивало DNS через туннель — например, использует собственный DoH или
  жёстко прошитый IP, — доменное правило не сработает. Предполагать, что
  sniffing «всё равно восстановит домен», нельзя; фактические срабатывания
  видны в наблюдениях по правилам на странице маршрутизации.
