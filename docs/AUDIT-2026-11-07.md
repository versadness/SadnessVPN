# Аудит Sadness VPN — 7 ноября 2026

Проверены исходники настольного клиента, границы локального API, жизненный цикл
Electron/Python/Mihomo, обработка подписок, сохранение настроек и оформления,
смена серверов, загрузка обновлений, установщик и инструменты выпуска.
Для Android выполнен ограниченный статический просмотр обновления, подписок
и импорта резервной копии. Это проверка конкретных сценариев, а не гарантия
отсутствия остальных ошибок.

Установленная 3.4.8 и ранее подготовленные EXE/MSI/MSP не менялись. Исправления
ниже находятся в исходниках и потребуют отдельной сборки нового кандидата.
Исходные незакоммиченные изменения владельца сохранены. Публикация не выполнялась.

## Что ещё требует работы

### Зависимости — P1

Свежие локальные проверки npm audit и pip-audit отметили зависимости, которые
пока не обновлялись. Это данные баз уязвимостей о версиях пакетов, а не
доказательство эксплуатации всех записей через Sadness VPN.

- npm audit: 20 зависимостей с предупреждениями — 1 critical, 14 high,
  5 moderate. Зафиксированы Electron 32.3.3, electron-builder 25.1.8,
  tar 6.2.1. Electron объявлен devDependency, но его runtime действительно
  поставляется пользователю, поэтому проверка только production dependencies
  скрыла бы существенную часть риска. Critical для tar относится к дереву
  инструментов сборки; не следует считать его отдельной подтверждённой атакой
  на установленный клиент. Предложенные audit исправления Electron/builder
  требуют смены мажорных версий.
- pip-audit: 70 записей об уязвимостях в шести пакетах. Certifi 2026.5.20 — 2,
  cryptography 46.0.7 — 7, Pillow 12.3.0 — 39, Werkzeug 3.1.6 — 1,
  pip 24.0 — 12, setuptools 65.5.0 — 9. Последние два прежде всего относятся
  к окружению сборки. Pillow обрабатывает загруженные изображения,
  cryptography используется для криптографии, Werkzeug — в локальном API.

Полные ответы аудиторов: `build/audit-2026-11-07-npm.json` и
`build/audit-2026-11-07-python-dependencies.json`. Версии библиотек и файл
package-lock.json в этой проверке не менялись. pip-audit установлен в отдельное
`build/audit-tools-venv`, а не в рабочее окружение приложения.

### Остальные операции с коллекциями профиля — P2

Исправлены проверенные сценарии маршрутизации и переименования групп, но
остальные CRUD-операции требуют такого же последовательного перехода к
сохранению кандидата перед изменением живого состояния. В частности,
`api_delete_group`, `api_delete_server`, `api_rename_server` в
`ui/routes/servers.py` и соответствующие WireGuard-обработчики ещё меняют
коллекцию до записи. При OSError от записи возможно расхождение памяти с
файлом. В части операций результат `_save_settings()` после записи коллекции
также игнорируется. Общая транзакция между несколькими JSON-файлами отсутствует.
Эта часть отмечена по коду; новые исправления в ней не объявлены проверенными.

### Android — статические замечания P2, без проверки на устройстве

- `data/Backup.kt`: число итераций PBKDF2 берётся из импортируемого файла без
  верхней границы до вычисления ключа. Специально подготовленная копия может
  надолго занять CPU; целесообразна валидация формата, размеров и KDF-параметров.
- `ui/DataScreens.kt`: импорт резервной копии использует readBytes без лимита
  общего размера. Большой входной файл способен исчерпать память.
- `ui/Updates.kt`: загрузка APK не ограничивается заявленным info.size;
  проверяется только необязательный хеш после загрузки. При ошибке чтения
  частичный файл остаётся в cache до следующего запуска загрузки.

Android SDK в стандартном каталоге окружения не найден; Gradle-тесты, сборка
APK и проверка Android VPN на устройстве не выполнялись. Эти замечания не
выдаются за подтверждённые эксплуатационные сценарии.
